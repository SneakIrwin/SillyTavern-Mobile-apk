# SillyTavern Secure Mobile audit - 2026-11-16

Scope: Android safe areas/lifecycle/updater, authenticated desktop gateway and stream relay, Windows tray/one-click launch integration, build and GitHub publication. Baseline was clean v0.1.8 (`5398fe3`). This was a concrete-defect audit, not a rewrite or a claim that every possible failure was eliminated.

## Repairs

- Reproduced large catch-up failures above 256 KiB. Relay subscribers now use a byte cursor and drain-aware pumping for both live and completed streams. Multi-megabyte replay is byte-exact, including offsets inside UTF-8 sequences, without duplicate upstream generation. Cancel/eviction/shutdown releases blocked subscribers.
- Rejecting encoded upstream streams now closes the upstream rather than leaving an indefinite generation outside active-relay accounting.
- Ordinary proxy truncation now fails the consumer promptly, not a hung HTTP 200 or appended error text. Ordinary consumer cancellation closes its upstream. These paths are separate from intentional mobile relay detachment.
- Re-pairing on a reused keepalive TCP connection now updates socket ownership. Revocation closes the current owner's upgraded socket and the upstream peer; gateway shutdown explicitly closes upgraded connections too. HTTPS upstream upgrades use TLS rather than raw TCP.
- Android install-source permission return refetches and revalidates the update. Pending confirmation retains callback identity until terminal result, active sessions block duplicate installation, and failed/denied retry paths offer a user-triggered Retry update button. A small pure-Java policy has executable ownership/orphan/clock/identity regression cases.
- Renderer or unclean process restart shows an honest dismissible interruption notice rather than implying recovered generation state.
- Live test harness requires an explicitly selected disposable emulator and isolated test CA, scopes every ADB command, and refuses implicit/physical targets before destructive commands. The normal test command now includes these safeguards and update-session regressions.
- Pinned `node-forge` 1.4.3; registry audit reports zero known dependency vulnerabilities. This is not proof that every installed/shared runtime is vulnerability-free.
- CA repair preserves existing trust; incomplete CA identity fails with restore guidance. Server-certificate validity/key/issuer/name checks permit leaf repair without rotating the CA.
- One-click hub readiness uses the common size/time-bounded body reader.
- Release APKs are non-debuggable and retain the verified old signer. Build/publication checks validate signer, package/version, embedded CA and hashes. Resource mapping accounts for release optimizer renaming.
- Build verifies installed SDK before attempting mutation, removes blanket acceptance of unrelated SDK licenses, and pins a versioned platform-tools 37.0.3 archive. The archive was independently checked against Google repository metadata; package payload hashes were mechanically updated from those verified bytes. Two missing Gradle metadata hashes were verified against the primary Maven Central artifacts/published checksums; strict verification remains enabled.

## Evidence and boundaries

- Baseline full suite passed. Updated full `npm test` passed, including 27 Android/harness/policy/release checks, 43 desktop checks and 4 license checks; focused proxy runtime tests passed 5/5. Stream checks include actual multi-megabyte HTTP replay and forced-drain terminal cleanup.
- Signed release build succeeded. `quality/release-signing.json` pins the v0.1.8 signer `e19a30327cb2b6500429ef6ad54f296f21dd4968842744b6340545d895f31456`. Updater artifact SHA-256 is `2dce8c9679ed22d951d77499fc0e4f134ffd727903681d4eec5fb4e9430aa932`.
- Native Sol and Terra audits supplied independently reproduced findings. Claude Fable 5.2 was attempted through the current native CLI review skill, first read-only (600 seconds) then one smaller prompt-only correction (120 seconds). Both returned no output and were timed out/owned-tree cleaned. No Claude verdict, exact runtime model or service setting is claimed. The lead made the final independent engineering decisions using source and tests.
- Native subagent API exposes no service selector, so its default service cannot be independently verified. No Fast service was requested.
- Production ST, gateway and tray were stopped and startup absent at baseline; audit preserves that activation choice. No live desktop UI was controlled, no phone app was cleared, and no new persistent trigger was added.
- Whole-process/page-state reconstruction and gateway restart durability remain separate features. Retained in-memory replay is bounded by expiry/capacity; the notice does not recover unsaved drafts or claim a generation was saved.
- Real Android PackageInstaller user-confirmation/grant/deny flows remain only partially covered by policy/source tests; a signer-compatible ADB install is not evidence of every system installer callback path.

Headless Android API 36 test passed using an isolated copied debug build and separate generated test CA: 10-second real screen sleep/wake, same app PID, relay offsets `[0,498]`, exactly 11,494 output bytes, one upstream request and no upstream cancellation. The production-signed non-debuggable release also installed successfully in the disposable emulator. The actual rendered interruption notice was inspected: readable, dismissible, and inside the status/gesture safe areas. This synthetic-page test is not a test of real SillyTavern unsaved-draft reconstruction, a physical phone, or every OEM background policy.

An actual v0.1.8 APK fetched from its published Release and hash-checked was installed in the disposable emulator, then upgraded in place to the new production release. A task-owned app-private sentinel survived the upgrade (checked after restoring the same-signer debug test build), and the release rejected `run-as` as non-debuggable. [Inspected interruption-notice screenshot](audit-2026-11-16-interruption-notice.png).

The two optional admin-relay checks refer to a local-only helper deliberately excluded from this public repository; they now skip only when that unrelated helper is absent. Product checks are unchanged. The executable Java policy test accepts JAVA_HOME, the local pinned JDK or system Java, so it does not require a private `.tools` directory in a public checkout.

The owned headless emulator and its QEMU child exited, the ADB device list was empty, and the audit-started ADB server was stopped. Automatic deletion of generated test directories was rejected by command review; no alternate deletion path was attempted. Retained local-only artifacts: `.tools/audit-20261116`, the isolated generated test CA fixture at `%TEMP%/st-mobile-audit-ca-1c61e94efb1547d1ad891a2ac9c9d047`, and the worker's `%TEMP%/st-mobile-javac-133c8847-14af-4b95-9f9f-a93eb4d15485`. They are not running, shipped or used by production. The pre-audit platform-tools backup remains deliberately recoverable under `.tools/platform-tools-before-audit-20261116`.

Publication readbacks are recorded in the task journal at closeout.

Hosted verification caught an Android build-tools 37 output-format change (`V2 Signer:` versus local `Signer #1`). The parser now recognizes both actual formats while requiring the exact pinned app-signing certificate, rejecting absent/different/multiple identities and source-stamp-only output. It has a regression fixture from the failed hosted job; APK bytes and the identity requirement were not changed.
